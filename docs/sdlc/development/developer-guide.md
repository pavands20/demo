<!-- sdlc:auto:start overview -->
This is 'demo', a RAG-chat project with a login page and Postgres database, generated by the Quorq AI SDLC platform as two independent apps in one repo. The frontend (frontend/) is a Vite + React 19 SPA whose screens were all reviewed and approved, but currently render seeded sample data rather than calling a real API. The backend (backend/) is a FastAPI 0.115 service scaffolded before any architecture was approved, so it only exposes a working /health check; everything else is stub routers waiting to be filled in. The intended stack is React + FastAPI + PostgreSQL 16 on AWS, though the backend defaults to local SQLite so it can run with no database server.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm/Vite 6, React 19 toolchain)
- Python 3.12
- pip
- Docker and Docker Compose (optional, for the Postgres service in docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. Copy .env.example to .env and fill in values as needed
3. cd frontend && npm install
4. cd backend && pip install -r requirements.txt
5. (Optional) Start Postgres with: docker-compose up db -- note the backend defaults to SQLite (app.db) unless DATABASE_URL is set to point at this Postgres instance
6. Run the backend (uvicorn app.main:app --reload) and the frontend (npm run dev) in separate terminals
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component under app/routers, one route per endpoint, each generated route starting as a stub returning schemas.StubResponse
- Backend models inherit app.database.Base; models.py is imported in main.py before Base.metadata.create_all so new tables register automatically
- No migrations yet -- schema is created directly from models on startup; replace with Alembic before storing real data
- Backend config via env vars: DATABASE_URL (defaults to local SQLite) and ALLOWED_ORIGINS (CORS, defaults to the Vite dev origins)
- Frontend uses a '@/' path alias to src/, Tailwind CSS v4 via @tailwindcss/vite, and a shared component/icon vocabulary in lib/ui.tsx and lib/icons.tsx
- Frontend API calls funnel through lib/api.ts's apiFetch, configured via VITE_API_BASE_URL and VITE_API_SECRET_KEY (bearer auth), though screens don't call it yet
- Vitest component tests live beside the components they test; Playwright specs live in e2e/ separate from Vitest's include globs
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend calls to the backend are blocked by CORS | Set the ALLOWED_ORIGINS env var (comma-separated) on the backend to the frontend's actual origin; defaults only allow http://localhost:5173 and http://127.0.0.1:5173 |
| `pytest` fails with `ModuleNotFoundError: app` | Run pytest from the backend/ directory so pytest.ini's `pythonpath = .` takes effect |
| Backend data doesn't match the approved Postgres architecture | Set DATABASE_URL to a Postgres connection string (e.g. the docker-compose db service); otherwise the app falls back to a local sqlite:///./app.db file |
| `npm run test:e2e` fails because no browser is installed | Run `npm run test:e2e:install` first to fetch Chromium |
| `npm run build` succeeds but `tsc` would fail | Run `npm run typecheck` separately -- build does not typecheck, so type errors (e.g. loosely-typed useState) can slip through |
